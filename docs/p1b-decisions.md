# P1b 设计决定

2026-11-13 定下 P1 详细设计里的两个待决问题（Q1、Q2），P1b 按本文实现。与设计文档的写法不同时，以本文为准。设计文档的连接恢复后，再把这些内容同步过去。

## Q1：门槛 2 拆开

**决定：拆开。**

设计文档原来的门槛 2 是“回答输出中手动断开当前线路，回答完整、出口 IP 不变”。这其实包含两种情况，P1 只能保证其中一种：

- **切换线路，旧线路仍可用**：已建立的连接留在旧线路上，回答完整。P1 保证。
- **旧线路物理断开**：经过它的 TCP 连接必然中断，正在输出的回答会断。P1 只保证新连接尽快恢复。要让在途回答也不断，需要在出口一侧保持会话，这留给 P2 的云端锚点调研。

**改写后的门槛 2**：

1. 切换线路时，回答完整，出口 IP 不变。
2. 线路物理断开后，新连接 5 秒内恢复。
3. VPN 或隧道断开后，从隧道恢复起 5 秒内新连接可用；这段断联归因为“本地”。
4. 一周内每次断联都有归因，“未知”占比低于 10%。

第 3 条是新增的。所有流量都经全量 VPN 时，最常见的断联是 VPN 重连，不是线路故障。2026-11-13 实测时，Astrill 重连过一次：隧道内部地址从 198.18.2.173 变成 198.18.0.60，出口 IP 不变。

**对验收测试的影响**：

- T4（VPN 断开重连）的通过标准加上时间上限：隧道恢复后 5 秒内可用。
- T1 到 T3 需要至少两条线路，在测试环境里用本机模拟线路来测，和 P1a 的端到端测试一样。只走 VPN、不配线路的实际用户环境测不了这三项。
- 在途回答中断属预期。Claude Code 遇到网络错误一般会自己重试，所以对它来说，新连接 5 秒内恢复基本等于任务不中断；网页版和桌面版正在输出的回答需要重新生成。

## Q2：出口 IP 变化时锁住通道

**决定：锁住，不是只通知。** 只通知的话，等用户看到通知时，AI 服务已经见过新 IP 了，“固定出口”就没有保证。

在设计文档“出口管理”一节的基础上，做三点改动，让锁住更及时，也更少打扰用户。

### 1. 出口回到基线时自动解锁

- 锁住之后，用户代理继续核对出口。出口 IP 回到基线，就自动解锁，通知用户“已恢复”，不需要用户操作。
- 只有在要接受一个新 IP 时，才需要用户确认：运行 `anchor baseline` 登记新基线，或者切到备用出口。
- 典型场景：在 VPN 客户端里误连了别的服务器。通道锁住；连回原来的服务器后，通道自动恢复。

### 2. 网络变化时立即核对

- 用户代理监听网卡和地址的变化（`NotifyIpInterfaceChange` / `NotifyUnicastIpAddressChange`）：VPN 重连、换网卡、隧道地址变化，都会触发立即核对，不用等 60 秒的定时核对。
- 60 秒的定时核对保留，用来发现本机网络没变、但出口那一侧换了 IP 的情况。

### 3. 网络变化后先核对再放行

- 一收到网络变化事件，就先锁住 AI 通道，核对通过后再放行。这样新 IP 上一个 AI 请求都发不出去。
- 核对的一个来源返回基线 IP，就立即放行。不一致时保持锁住，再用第二个来源确认；确认变化后记录 `exit_ip_changed` 并通知用户。
- 代价是每次 VPN 重连多 1 到 2 秒不可用。重连期间本来就连不上，多出的这点时间几乎察觉不到。
- 定时核对仍然要两个来源确认才锁住，避免回显服务偶发出错时误锁。

### 核对不了时：保持锁住

锁住后，如果所有回显服务都连不上、无法核对，就**保持锁住**，同时通知“无法核对出口”。出口绑定在固定的网卡或固定的节点上，真出问题时本来就连不上，保持锁住不会额外损失什么。

### 实现思路

- 锁住和放开不重启内核：sing-box 路由里加一条 `clash_mode` 为锁定模式时拒绝 AI 入站的规则，用户代理经 Clash API 切换模式。
- 内核重启后，用户代理重新应用当前的锁定状态。
- 用户代理自己的探测走单独的、带认证的探测入站，不受锁定影响，所以锁住期间仍能核对出口。
- 时间线新增事件：`exit_locked`、`exit_unlocked`（原因：回到基线、用户登记新基线、切换出口）、`exit_ip_changed`、`exit_unverifiable`。

### T5 改为四个用例

| 编号 | 用例 | 通过标准 |
| --- | --- | --- |
| T5a | 网络变化导致出口变化（VPN 客户端切到别的服务器） | 锁住期间，AI 入站的新连接全部被拒绝；新 IP 上没有任何 AI 请求发出；通知用户 |
| T5b | 本机网络不变，出口那一侧换了 IP | 2 分钟内锁住并通知 |
| T5c | 锁住后切回原来的出口 | 自动解锁，不需要操作；网络变化后 10 秒内恢复 |
| T5d | VPN 重连，出口不变 | 锁住不超过 3 秒，自动放开；不发通知，只记时间线 |
